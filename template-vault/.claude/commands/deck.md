# /deck — Prepare a presentation

Target: **$ARGUMENTS**.

Read the buyer’s problem, existing proof and presentation-craft convention. Choose presentation or document mode for the audience. Outline one idea per slide: the actual problem, supported impact, product/workflow demonstration, proof, scope and next step. Include pricing only when authorized. Use a consistent product shell for a demo; label mockups as concepts and use anonymous realistic sample records. A working-product claim requires real evidence. Specify captures that are missing; never disguise a planned capability as shipped. Make numbers traceable and omit unsupported claims. Save under strategy/Decks. For an authorized visual build, inspect every rendered screen, keyboard/touch navigation, mobile layout and reduced motion before reporting completion. Publishing needs explicit authorization.


Use the installed owner profile and chosen assistant identity. Search before creating pages. Follow `_system/conventions/filing.md`, `_system/conventions/source-attribution.md` and `_system/doctrine/completion-status.md`. Create task output folders only when needed. Referenced account records and banks are optional evidence, not assumed facts. Drafting never grants permission to send or publish.
