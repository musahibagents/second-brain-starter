# /handoff — Write an actionable build specification

Target: **$ARGUMENTS**.

Read the project, calls, constraints, commitments and existing system records. Write systems/<project> Spec.md with the stated ask (exact quotes only when available), underlying outcome, users and current workflow, scope and exclusions, data and integrations, known constraints, explicit unknowns, already-promised commitments, acceptance criteria, risks and next decisions. Distinguish known facts from proposed architecture and unconfirmed estimates. Technical work belongs to the current owner/team; never invent a mandatory external approver. A specification does not by itself authorize implementation. If the owner has explicitly authorized building, proceed within that scope. Link the specification from the project and summarize the outstanding decisions.


Use the installed owner profile and chosen assistant identity. Search before creating pages. Follow `_system/conventions/filing.md`, `_system/conventions/source-attribution.md` and `_system/doctrine/completion-status.md`. Create task output folders only when needed. Referenced account records and banks are optional evidence, not assumed facts. Drafting never grants permission to send or publish.
